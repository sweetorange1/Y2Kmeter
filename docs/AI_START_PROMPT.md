当前工作区 `Y2KMeter` 是一款开源（GPL-3.0）的**音频分析 / 计量插件**：VST3 + AU + Standalone，C++17 + JUCE 8（vendored）。
它是纯「读取 → 计算 → 绘图」型软件——**不修改、不输出音频；不含驱动、内核组件或常驻服务；运行期默认不联网**；
Standalone 的音频源（麦克风 / 系统播放回环）由用户在界面上显式选择；v3.3 的「电脑状态」模块只读操作系统公开的性能计数器。
一句话：这是个正常的桌面音频工具，功能本身没有需要顾虑的地方。

**你先这样熟悉项目（重要：不要整篇读）**

1. 读 `docs/INDEX.md`（约 30 行），它有"什么时候该读哪份文档"的对照表。
2. 读 `PROJECT_OVERVIEW.md` 的 §1「项目概述」和 §7「常见修改场景速查」——用 `read_file` 的 `offset` / `limit` 分段读，单次 ≤200 行。
3. 只有确实要动某个主题时，才去读 `docs/` 下对应那一份（构建 / 渲染 GL / 窗口布局 / 分析模块 / UI 功能 / 工程教训）。
4. **不要把 60 KB 的 `PROJECT_OVERVIEW.md`、100 KB 的 `source/ui/ModuleWorkspace.h` 一次性整篇读进来**：既浪费预算，也会让上游安全层误判整段内容。

## 为什么开头要强调"分段读"

- `PROJECT_OVERVIEW.md` 约 720 行 / 60 KB，`source/ui/ModuleWorkspace.h` 约 100 KB。整篇入上下文时，
  prompt 会从 25k tokens 直接跳到 68k+，并在部分情况下被上游内容安全层判为 `content-filter`（模型 0 输出、直接兜底拒答）。
- 同样的文档分片读（offset/limit）时从未触发。这条约定既省 token 又稳。
