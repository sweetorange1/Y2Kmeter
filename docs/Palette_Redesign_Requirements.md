### 1.2 为什么"笨"、为什么"不好看"（根因）

1. **派生算法不感知人眼色彩。** `darker()/brighter()` 在 HSB 的 B 通道上做倍率运算，同一档位在不同色相上的明度/饱和度表现差异巨大：黄色一压就脏，蓝紫一提就刺眼；`pink700 = brighter(0.40)` 在很多色上接近纯白，`pink50 = darker(0.65)` 接近纯黑，梯度两端"死掉"。
2. **没有色相偏移与饱和度管理。** 手工预设之所以好看，是因为暗部偏冷/偏暖、亮部降饱和、背景带一点主色倾向；自定义主题的所有色阶都是同一色相的机械缩放，天然"塑料感/脏灰"。
3. **两个输入含义不直观。** "Accent"与"Base"对用户来说不是自然概念；默认 Base = 纯白，用户随手选一个 Accent 就得到"白底 + 一个色"的寡淡结果；用户选 Base 时无法预知它会同时影响背景、边框、按钮面、文字色 4 类东西。
4. **没有质量护栏。** 不检查对比度（`ink` 对 `content`、`selInk` 对 `sel`）、不限制背景饱和度、不保证图表色阶的明度单调；用户一旦选了"危险色"，整套界面就崩。
5. **操作方式间接。** 用 RGB/HSB 滑块在两个 `ColourSelector` 里"盲调"，改完要点 Apply 才知道效果，缺少实时预览、对比、撤销；没有"一键给我一套好看的"。
6. **预设与自定义是两套体系。** 预设是 19 色手工全指定，自定义是 2 色算法生成，品质落差大；预设无法被"微调"，只能整套替换；自定义也不能保存为命名主题。
7. **图表渐变质量问题。** Spectrogram 等用 `interpolatedWith` 在 sRGB 空间线性插值，两色之间的中段容易发灰发脏；且图表只有"单色相阶梯"，缺少第二强调色，视觉层次单一。

## 2. 产品目标与非目标

### 2.1 目标

- G1 **一步出好看**：用户只拖动 1 个"色相"控件（或点一次"随机"），就得到一套完整、协调、对比度合格的主题。
- G2 **所见即所得**：调整过程中，真实工作区（所有模块）实时变化，不需要先 Apply 再看结果。
- G3 **可微调不推倒**：在生成结果上，用户可以只改某一个角色（如强调色、背景），其余自动保持协调。
- G4 **自定义 = 一等公民**：可命名保存多套、可导入导出/分享、可基于任何预设二次编辑。
- G5 **质量有底线**：任何用户输入都不会产生不可读、不可用的界面（自动护栏）。
- G6 **向后兼容**：旧存档（`ui.themeId`、`ui.customPrimary/Secondary`）无损迁移；模块代码不必大改。

### 2.2 非目标（本期不做）

- 不改各模块的绘制逻辑与布局；不做每模块独立配色。
- 不做 alpha / 透明度主题化。
- 不引入新的第三方依赖。
- 不重做桌面纹理绘制（仅允许自定义主题选择已有 7 种纹理之一）。

## 3. 核心设计理念

> **"选意图，不选数值。"** 用户表达的是"我想要偏粉的暗色、饱和一点"，而不是 `#EC4D85`；数值由生成器负责，并且在感知均匀的色彩空间里计算。

三层结构：

```
 用户意图层（简单）  : 色相 / 明暗 / 氛围(饱和度) / 和谐方式 / 随机
        │  ThemeSpec（可保存的小数据）
        ▼
 生成层（算法）      : OKLCH 色彩空间 + 配方(Recipe) + 护栏(Guardrails)
        │  语义角色 Roles（约 10 个）
        ▼
 映射层（兼容）      : 展开成现有 19 个 PinkXP 槽位 + 新增图表渐变
```

## 4. 功能需求

### 4.1 入口与整体交互

- R1 左下角色票条保留，但升级为：`[当前主题预览块]  [预设色票 x 12]  [我的主题 x N]  [+ 新建/编辑]`，当前主题名仍显示。
- R2 点击"预览块"或"+"展开**调色面板**（替换现有 `CustomThemePicker`）。面板需可拖离/不遮挡主要预览区域，或采用半透明停靠方式，使用户能同时看到模块变化。
- R3 面板打开期间所有改动**实时作用于整个工作区**；底部提供「应用并保存」「还原」两个动作：
  - 还原 = 回到打开面板时的主题；
  - 关闭面板（点外部/Esc）默认保留当前效果但标记为"未保存"（未命名主题），避免用户误丢劳动成果。
- R4 支持撤销/重做（至少 20 步）与 A/B 对比（按住某键/按钮临时显示打开面板前的主题）。

### 4.2 一级控件：简单模式（默认视图，覆盖 90% 使用）

| 控件 | 说明 | 行为 |
|---|---|---|
| **色相环** | 单个圆环 + 拖点，直接选主色相（0-360） | 拖动时实时刷新；环上的颜色已按"该色相在当前明暗下的最佳显示色"渲染，所见即所得 |
| **明暗切换** | `Dark / Light / Auto-mid`（3 段按钮） | 切换整套背景/文字的明度策略（见 §5.2） |
| **氛围(Vibe)滑条** | `Soft ←→ Vivid`，即整体饱和度/强调色浓度 | 同时影响强调色 chroma、背景染色强度、图表渐变饱和度 |
| **和谐方式** | `Mono / Analogous / Complementary / Split / Triad` 图标按钮 | 决定"第二强调色(accent2)"相对主色相的偏移，用于图表渐变与高亮 |
| **背景染色** | `Neutral ←→ Tinted` 滑条 | 背景是否带主色倾向 |
| **🎲 随机** | 从"精选配方库"生成一套完整主题；可连续点；每次结果入历史，可回退 | 不是纯随机 RGB，而是随机选 (色相, 明暗, 和谐方式, 氛围) 的**合法组合** |
| **🔒 锁定** | 在随机时可锁定"色相/明暗/某角色" | 实现"我喜欢这个粉，只换背景风格" |

- R5 简单模式下**不出现**任何 RGB/HSB 数值或十六进制输入。
- R6 色相环上直接取色吸管：支持"从屏幕取色"（Standalone 可选），取到的颜色经"吸附"进生成器：只取其色相与偏好浓度，而非直接使用。

### 4.3 二级控件：角色微调（折叠"高级"）

只暴露**语义角色**，不暴露 19 个槽位。建议角色（约 8-10 个，最终以实现为准）：

| 角色 | 含义 | 影响的现有槽位 |
|---|---|---|
| Accent 主强调色 | 标题栏、推子轨道、选中、图表主色 | `sel`、`swatch`、`pink400` |
| Accent2 次强调色 | 图表渐变终点、次级高亮 | 新增（图表渐变 / `pink600-700`） |
| Background 桌面背景 | 窗口外桌面底 | `desktop`、`desktop2` |
| Surface 模块画布 | 模块内容区底色 | `content` |
| Control 控件面 | 按钮/边框面 | `btnFace`、`face`、`hl`、`shdw`、`dark` |
| Text 正文文字 | 正文墨色 | `ink` |
| OnAccent 强调色上的文字 | 标题栏文字 | `selInk` |
| Chart Ramp 图表渐变 | 由 Accent→Accent2 自动生成 N 阶 | `pink50..700` |
| Danger/Warn/OK（可选） | 过载/临界/安全状态色 | 现 `sel`/`pink500`/`pink200` 的语义用法 |

- R7 每个角色一行：色块 + 十六进制输入 + 小吸管 + "自动/手动"开关。
  - **自动**：由简单模式的结果推导（默认）；
  - **手动**：用户改过的角色被"锁定"，之后再调色相/氛围时该角色不再被覆盖。
- R8 手动改某角色时，**其关联角色自动协调**（例如改 Background，则 Control 面/边框/Surface 随之按配方重算，除非它们也被锁定）。
- R9 取色器统一使用一个轻量的**饱和度-明度方块 + 色相条**（替代两个 `juce::ColourSelector` 的臃肿布局），尺寸小、风格贴合 Y2K UI。

### 4.4 预设、我的主题、分享

- R10 现有 12 个预设保持**外观不变**（手工调校的成品，视觉回归零容忍），但在新体系中作为"带完整覆盖的种子主题"，可被"基于它新建"：选中预设 → 点"编辑" → 在此基础上改色相/氛围/角色。
- R11 「我的主题」：
  - 可命名保存、重命名、删除、排序；至少支持 12 个；
  - 出现在色票条上（与预设同样的色票样式，区别于预设以小角标）；
  - 每个自定义主题保存：`ThemeSpec`（意图参数）+ 各角色手动覆盖 + 桌面纹理 + 标题图标。
- R12 **导入/导出/分享**：
  - 复制为一段短文本分享码（如 `Y2KT1-xxxxxxxx`，Base64 压缩 ThemeSpec，不超过 ~80 字符），可在应用内粘贴导入；
  - 可选导出/导入 `.y2kpalette`（JSON/XML）文件。
- R13 提供「恢复默认主题(Reset)」入口（回到 `blackPink`）。
- R14 自定义主题可选择**桌面纹理**（现有 7 种）与**标题图标字符**（给 5-8 个候选），不再固定为 `checker`/`+`。

### 4.5 预览与反馈

- R15 面板内含一个**迷你预览卡**（标题栏 + 按钮 + 推子 + 一小段频谱渐变 + 文字），即使工作区被面板遮挡也能看到效果。
- R16 面板内展示**对比度/质量徽章**（见 §5.3）：全部通过时显示 ✓；被自动修正时给出轻提示（如"文字已自动提亮以保证可读"），不打断用户。
- R17 色票悬停 tooltip 保留；新增预设/主题的"氛围标签"（如 `Dark · Neon · Y2K`）便于筛选（可后期）。

### 4.6 持久化

- R18 Standalone：用户主题库、当前主题、当前 `ThemeSpec` 存入 `getUserSettings()` 现有键体系（新增 `ui.themeLibrary` 等，保留 `ui.themeId`）。
- R19 **VST3 插件模式也要保存当前主题**（至少随宿主工程保存），消除现状的行为差异（需结合 `PluginProcessor` 的 state 机制评估，如不可行需明确声明限制）。

- R22 排查 `Y2KStandaloneApp.cpp` ~1026 附近"按 key 保护式重写"列表，确认新增键不会在启动/退出路径被丢弃（现有 `ui.customPrimary/Secondary` 是否在列表中需核实）。

## 5. 生成算法需求（"好看"的核心）

### 5.1 色彩空间与基本要求

- A1 内部统一用 **OKLCH**（感知均匀的明度 L / 彩度 C / 色相 H）计算，最终转 sRGB。
- A2 所有生成颜色必须经过**色域裁剪（gamut clamp）**：超出 sRGB 时降 C 保 L、H，而不是通道截断（避免偏色）。
- A3 渐变/插值在 OKLab 中进行，替代 sRGB 线性插值（解决中段发灰）。
- A4 纯 C++ 实现，不依赖 JUCE UI，便于单元测试（与项目现有 DSP 冒烟测试风格一致）。

### 5.2 配方（Recipe）：由 (H, 明暗, Vibe, 背景染色, 和谐) → 角色

下表为**起步调优目标**，具体数值在实现阶段通过"黄金截图评审"迭代，不作为硬编码承诺。

| 角色 | Dark 模式 | Light 模式 |
|---|---|---|
| Desktop 背景 | L 0.14-0.20；C = 0.005 + 0.03 x 染色 | L 0.78-0.88；C = 0.01 + 0.05 x 染色 |
| Surface 画布 | 比 Desktop 高 L +0.02~0.04，C 略低 | L 0.96-0.985，C 极低 |
| Control 控件面 | Surface 上 L +0.04~0.06 | Surface 下 L -0.04~0.06 |
| 边框四色 (hl/face/shdw/dark) | 以 Control 为中心，沿 L 上下按固定步长（保证 Win95 立体感：高光 > 面 > 阴影 > 最深） | 同左 |
| Accent 主色 | L 0.68-0.80，C 取 Vibe 映射（0.08~0.26，裁到 gamut 最大） | L 0.50-0.65，C 同左 |
| Accent2 | 主色相按和谐方式偏移（Mono: ±0 但 L 偏移 + 小 H 漂移 15°; Analogous ±30°; Complementary +180°; Split +150°; Triad +120°） | 同左 |
| Text 正文 | L 0.92-0.96，C 0.01-0.02，带主色相微倾向 | L 0.18-0.25，C 0.01-0.02 |
| OnAccent | 在 Accent 上选对比度最高的"近黑/近白"（带微染色，不用纯黑纯白） | 同左 |
| Chart Ramp | N=8 阶，L 单调递增（0.28→0.92），C 呈"中间峰值"曲线，H 在 Accent→Accent2 之间平滑漂移（Bezold-Brücke 补偿：暗部偏冷、亮部偏暖） | 同左，L 范围整体偏移 |

- A5 **氛围(Vibe)** 单一滑条映射为：Accent 的 C、背景染色上限、Chart Ramp 的 C 峰值；Soft 端要有"粉彩/莫兰迪"感，Vivid 端要有"霓虹"感，但都不脏。
- A6 **Auto-mid** 模式：背景 L 约 0.45-0.55（中间调），用于"XP 蓝"这类彩色桌面风格，需要单独校对文字色策略。
- A7 配方内置的"精选 Recipe 库"（供随机按钮使用）至少 20 组 (H 分布 / 明暗 / Vibe / 和谐) 合法组合，并附带人工评审通过标记，确保随机的**下限质量**。

### 5.3 护栏（Guardrails）

| 编号 | 规则 | 违反时的处理 |
|---|---|---|
| Q1 | `Text` 对 `Surface`、`Text` 对 `Control` 对比度 ≥ 4.5:1（WCAG 近似；可用 OKLab L 差替代阈值） | 自动调整 Text 的 L |
| Q2 | `OnAccent` 对 `Accent` ≥ 4.5:1 | 在近黑/近白间自动选更优者 |
| Q3 | `Accent` 对 `Desktop`/`Surface` 的 L 差 ≥ 0.25（保证强调色可见） | 自动提亮/压暗 Accent（保 H） |
| Q4 | 背景 C 上限（Dark ≤ 0.05，Light ≤ 0.08） | 超出则按比例收敛 |
| Q5 | Chart Ramp 的 L 严格单调，相邻阶 ΔL ≥ 0.05 | 重新分配 |
| Q6 | 边框四色保证 `hl > face > shdw > dark` 的 L 顺序与最小间距 | 重新分配 |
| Q7 | 用户**手动覆盖**的角色，仍然执行 Q1-Q3，但仅给出**提示 + 一键修复**，不强改用户值（尊重意图，同时防呆） | 提示 |

## 6. 架构与兼容性需求

- S1 新增独立模块（建议）：`source/ui/palette/`
  - `ThemeSpec`（意图参数 + 手动覆盖，可序列化）
  - `PaletteGenerator`（纯 C++，OKLCH 工具 + Recipe + Guardrails）
  - `ThemeLibrary`（预设 + 我的主题 + 持久化）
  - `PalettePanel`（新 UI：色相环、滑条、高级角色、预览卡）
- S2 `PinkXP::applyTheme/applyCustomTheme` 保留为**对外 API**，内部改为：`ThemeSpec → PaletteGenerator → Theme(19 槽位 + 新增字段) → 原有写入 + 通知流程`。各模块**无需改动**即可享受新配色。
- S3 `Theme` 结构向后兼容扩展：新增 `accent2`、`chartRamp[8]`、`danger/warn/ok`（可选）；原 19 槽位语义不变。
- S4 模块逐步迁移：

## 7. 验收标准

### 7.1 功能

- AC1 打开面板，只拖动色相环，在 **任意色相 x {Dark, Light} x 3 档 Vibe** 的组合下，整套界面均无不可读文字、无"死白/死黑"色阶、无明显脏灰。
- AC2 点「🎲」连续 30 次，评审人员认为"可直接使用"的比例 ≥ 80%（人工评审，设定基线）。
- AC3 面板打开时工作区实时变色；「还原」可回到打开前；撤销/重做可用。
- AC4 保存 ≥ 3 个自定义主题，重启后全部恢复；复制分享码在另一台机器粘贴导入，外观一致。
- AC5 升级后，旧存档（预设 / custom）启动无异常，外观与旧版一致（预设）或接近且不更差（custom 迁移）。
- AC6 VST3 模式下主题可保存与恢复（或明确限制并文档化）。

### 7.2 质量（可自动化）

- AC7 `PaletteGenerator` 纯 C++ 单元/冒烟测试：遍历 H 步进 5°、明暗 2 种、Vibe 5 档，断言 Q1-Q6 全通过、无 NaN、均在 sRGB 色域内。
- AC8 "黄金色板"快照：对 ≥ 12 组代表参数，输出 19 槽位十六进制，存档比对，防止算法改动无意变化。
- AC9 性能：面板拖动时单次主题重算 < 1ms；全量刷新不引起主线程掉帧超过一帧。

## 9. 风险与注意事项

- **审美主观性**：用"总览图 + 黄金色板"把主观判断前置到 P0，评审通过再实现 UI。
- **旧存档**：`ThemeId::custom=11` 不可改序；存盘新增键需确认不被"保护式重写"列表过滤（§4.6 R22）。
- **性能**：实时预览会高频触发所有模块重绘，需要节流与缓存策略（§6 S6）。
- **预设保真**：预设必须是数据驱动原值，不要被新算法重新生成（§6 S7）。
- **VST3 持久化**：与 `PluginProcessor` state 的关系需先调研，可能涉及宿主兼容性。
- **文档修正**：`PROJECT_OVERVIEW.md` 中"10 个主题""主题保存在 `<PBEQ_Layout>`"等描述已与代码不符，重构完成后一并更新。
